# Дневной бюджет

Трекер дневного бюджета с переносом остатка для iPhone. Это PWA на чистом HTML, CSS и JavaScript: без сервера, библиотек, сборки и аккаунтов.

Сумма на месяц делится на дни, а лимит пересчитывается так:

```
лимит на сегодня = перенос + бюджет × (номер дня / дней в месяце) − потрачено с начала месяца по сегодня
```

Остаток переходит на следующий день, перерасход уходит в долг на следующие дни. В конце месяца остаток или долг переносится на 1-е число.

## Структура

| Папка | Что внутри |
|---|---|
| `docs/` | Само приложение. На хостинг выкладывается только эта папка |
| `docs/core.js` | Логика и формулы, без интерфейса и сети |
| `docs/app.js` | Интерфейс |
| `docs/sw.js` | Работа без интернета и обновления |
| `docs/boot.js` | Экран восстановления, если приложение не смогло запуститься |
| `tests/` | Модульные, статические и браузерные тесты |
| `tools/` | Значки, версия, локальный сервер |

Папка называется `docs`, потому что GitHub Pages умеет публиковать без настройки только корень репозитория или папку `docs`.

## Установка на iPhone

1. Выложи папку `docs/` на любой бесплатный хостинг статических файлов с HTTPS (раздел ниже).
2. Открой ссылку на iPhone в Safari, с интернетом.
3. Нажми «Поделиться» → «На экран “Домой”». Если есть переключатель «Открыть как веб-приложение», оставь его включённым. Нажми «Добавить».
4. Открой приложение с главного экрана и один раз дождись загрузки с интернетом. Дальше оно работает офлайн.

Начинай вводить данные только в установленном приложении: хранилище вкладки Safari с ним не связано.

## Что проверить на iPhone

Автотесты идут в Chrome с размерами экрана iPhone и в WebKit для macOS. Несколько вещей можно проверить только на самом телефоне:

- [ ] Значок и название «Бюджет» на главном экране, запуск без адресной строки.
- [ ] Включи авиарежим, закрой приложение смахиванием и открой снова.
- [ ] Запиши трату, сразу закрой приложение смахиванием и открой снова: трата на месте.
- [ ] Клавиатура не закрывает сумму, категории и кнопку «Записать».
- [ ] Настройки → «Сохранить»: открывается меню «Поделиться», файл сохраняется в «Файлы».
- [ ] Настройки → «Восстановить»: сохранённый файл выбирается и читается.
- [ ] Поле даты выглядит нормально и не вылезает за край.
- [ ] Настройки → строка состояния: «Работа без интернета: готова». Там же видно, подтвердила ли система защиту от автоочистки.

## Публикация

### GitHub Pages

1. Создай публичный репозиторий (на бесплатном тарифе Pages работает только с публичными).
2. Загрузи в него содержимое папки `budget`.
3. Settings → Pages → Deploy from a branch → ветка `main`, папка `/docs`.

Ссылка будет вида `https://имя.github.io/репозиторий/`. Код виден всем, траты остаются на телефоне и в репозиторий не попадают.

Хранилище браузера общее для всех проектов на одном домене `имя.github.io`. Страница другого твоего проекта на этом домене могла бы прочитать или стереть данные, введённые во вкладке Safari. У установленного приложения хранилище своё, поэтому важно пользоваться именно им.

### Другие варианты

Cloudflare Pages и Netlify тоже бесплатно публикуют статические файлы. При настройке укажи папку `docs`, команда сборки не нужна.

## Обновление приложения

После любого изменения в `docs/` обязательно поставь новую версию, иначе телефон не узнает об обновлении:

```sh
npm run stamp
npm test
npm run e2e
npm run webkit
```

Затем выложи изменения. При следующем запуске с интернетом приложение скачает новую версию и предложит «Обновить». Данные при этом не меняются.

Перед установкой обновления приложение сверяет контрольную сумму каждого файла. Если хостинг отдал что-то не то (старый файл из кэша CDN, страницу ошибки), обновление не ставится, а телефон продолжает работать на прошлой версии и проверит снова позже.

Если меняется формат данных, увеличь `SCHEMA_VERSION` в `core.js` и добавь перенос старых данных. Иначе новая версия не сможет прочитать данные и покажет экран «Данные не читаются». При этом сами данные останутся нетронутыми.

## Разработка

Нужен только Node.js 22 или новее. Устанавливать ничего не требуется.

```sh
npm run serve   # http://localhost:4173
npm test        # логика и исходники
npm run e2e     # сценарии в Chrome с экраном iPhone 15 Pro Max
npm run webkit  # проверка в движке WebKit через системную библиотеку macOS
npm run icons   # перерисовать значки
```

Снимки экранов во время браузерных тестов: `E2E_SHOTS=папка npm run e2e`. Один сценарий: `E2E_ONLY=часть-названия npm run e2e`.

## Приватность и безопасность

- Траты лежат только в памяти браузера на телефоне (`localStorage`). Аккаунтов, аналитики, рекламы и своего сервера нет.
- Код приложения не содержит сетевых запросов. Политика безопасности браузера (CSP) дополнительно блокирует запросы из кода страницы и загрузку файлов со сторонних адресов. CSP не перекрывает всё (например, переход на другую страницу), но чужому коду в приложении взяться неоткуда: сторонних скриптов нет, а текст пользователя не выполняется.
- Приложение обращается в сеть только за собственными файлами при установке и проверке обновлений. Хостинг при этом видит обычные данные запроса (IP-адрес, время, какой файл), но не траты.
- Текст пользователя выводится только как текст, поэтому заметка не может выполниться как код. Импорт проверяет весь файл до замены данных.
- Шифрования и PIN-кода нет: это сознательное решение. Защита данных на телефоне — его блокировка. Файл резервной копии не зашифрован, храни его в надёжном месте.
